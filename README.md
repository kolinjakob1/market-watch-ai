# HustleWatch

Sports scanner discovers all open Polymarket US sports moneylines, including games started in the preceding eight hours and upcoming games within 48 hours. Discovery has no league whitelist. The reference catalog is refreshed each scan, with mappings for US leagues, women's college basketball, international basketball, soccer, MMA, boxing, cricket, esports and active ATP/WTA tournaments. Actual odds coverage depends on the provider; unmatched markets are explicitly UNRATED/PASS. Three-way/draw markets are not treated as equivalent to two-way contracts.

The primary report ranks up to ten distinct games against margin-removed book consensus, one direction per game, and retains both live and upcoming coverage when available. It requires exact team names and start times within 15 minutes, three fresh books, limited disagreement, open uncrossed exchange quotes, known fees and a net model edge of three cents after fees and buffer for BUY. Live book quotes must be no older than 60 seconds and exchange samples no older than 30 seconds. Pregame books may be up to five minutes old. PASS candidates include a maximum entry price. Additional sports without verified comparison data are UNRATED/PASS, never fabricated BUY recommendations. If fewer than ten valid games exist, the report states the shortfall. Every report repeats current ranked candidates without two-hour suppression; messages split at Telegram limits so picks are never cut off. No bets are submitted; consensus estimates are unvalidated and fills are not guaranteed.

Market discovery uses the documented `marketTypes=moneyline` filter and paginates to exhaustion; it fails visibly rather than silently truncating at its safety cap. Odds API credits are used once per represented supported league per scan. API quota exhaustion fails the workflow and triggers the existing failure alert. Ten-minute sports scheduling is best effort: GitHub Actions can start late or skip schedules and cannot guarantee delivery by a deadline.

Stock/options workflow maintains `paper_state.json`, a **local simulator**, initially $500. It never submits broker orders. Momentum v1 considers bullish moves between 2% and 8% above the prior close. It uses current IEX quotes for stocks; eligible OPRA calls take preference if 7–21 days out, within 5% of underlying, fresh, and affordable. OPRA entitlement denial is reported with stock fallback. Options discovery checks the first 1,000 filtered contracts, not the entire market. The workflow scans 30 liquid stocks/ETFs and reports ten candidates with SETUP/WAIT/BLOCKED reasons; change WATCHLIST to expand. It does not cover all US stocks.

Simulation buys at ask plus 0.1%, sells at bid minus 0.1%, limits each position to $100 and total positions to three, and allows one entry per underlying per date. Stock stops/targets are -2%/+4%; option stops/targets are -20%/+30%. Fifteen minutes before session end it attempts exits. Sales proceeds are withheld until a later weekday regular-session evaluation. Stops are evaluated only on scheduled scans; gaps and missing quotes can cause larger losses. Stale quotes never fill. Marked equity can retain an old mark when data is unavailable. Expired or delisted contracts require manual reconciliation if session-close exits were missed. This is not a full broker execution/settlement model.

Completed simulated trades retain entries, exits, reason, strategy version and P&L. Logging creates a dataset for later evaluation; there is no automatic ML training or proven strategy. On weekends the workflow reports closed status without inventing trades. Telegram acknowledges delivery, while errors fail visibly. The ledger is persisted even if alert delivery fails.

Run `python -m unittest -v` for regression tests. Run `python scanner.py --dry-run` to evaluate sports without sending alerts (ODDS_API_KEY required). Set `DRY_RUN=1` for paper evaluation without Telegram; this still updates the local simulation ledger.


Crypto runs the closed-five-minute-bar breakout strategy, allowing the last three completed candles (at most 15 minutes old) to accommodate delayed scheduled runs without chasing more than 0.8% above the breakout close, on BTC, ETH, SOL, AVAX, LINK, LTC, BCH, DOGE, UNI and AAVE USD pairs. Every scan sends prices and HOLD/WAIT/BLOCKED diagnostics instead of a once-daily heartbeat. Missing/stale data never creates an entry; an all-quote outage fails visibly. Its separate local $500 ledger keeps a $125 allocation cap, two-position cap, fees, stops, targets and cooldowns. Persistence runs even if Telegram fails. Paper BUY means a simulated position was recorded; it is not a broker order. A lack of qualifying breakouts is not repaired by forced fills.


## Scan clock

`cadence.yml` keeps one dispatcher running, instead of relying on a new GitHub cron event for each scan. It starts crypto at UTC minutes 03/08/13/18/23/28/33/38/43/48/53/58; sports at 02/12/22/32/42/52; stocks at 04/09/.../59 in the existing weekday UTC 13–21 window, plus a weekend 16:14 status report. Each dispatched scanner checks out current main and retains its existing concurrency, ledger and failure notification behavior. Individual scanner workflows are manual/API only; their old cron and push triggers are removed to avoid duplicate scans.

The first deployment uses a 90-second clock session to verify replacement handoff immediately. Subsequent sessions run 55 minutes and require an accepted self-dispatch before ending. An hourly cron at minute 11 provides recovery if a worker dies; it can still be late. Scanner API dispatch is retried, sustained dispatch failure fails visibly, and the existing Telegram failure workflow also watches the clock. Disable the Cadence Scheduler workflow in Actions to stop the clock and its queued successors.

This improves launch cadence but is not a real-time guarantee: GitHub runner queues, outages, handoff and data/Telegram latency can delay scans and delivery. Run creation, job start, scan start and alert delivery are different timestamps. The scheduler deliberately runs only while this repository is public, where standard GitHub-hosted Linux runners are free; changing it to private stops this scheduler rather than silently consuming continuous billed minutes. It does not change repository visibility. A separately hosted scheduler remains the durable option for strict uptime.

## News scanner prototype

`news_scanner.py` reads Alpaca's stock and crypto news endpoint with the existing Alpaca credentials. It requests the broad feed by default; optional `NEWS_SYMBOLS=AAPL,TSLA,BTCUSD,ETHUSD` narrows coverage. This is provider coverage, not all news on the internet or a direct MarketWatch.com integration. No new subscriptions are purchased.

The **HustleWatch News Alerts** workflow previews on code pushes: it fetches and previews headlines without sending Telegram or modifying state. Its checkout uses the selected branch. Scheduled dispatches and manual runs (default `deliver=true`) send up to ten eligible headlines with source URLs, publication/update times, and feed age. Access can be delayed 15 minutes; polling adds further delay. Live API access was verified by the branch preview workflow. News dispatches every ten minutes at UTC minutes 06/16/26/36/46/56, including weekends, using the existing continuous cadence worker. Coverage remains provider-dependent.

Articles updated within the last hour are eligible, including corrections to older stories within the requested two-hour window. IDs plus update timestamps suppress duplicates. Accepted alerts are saved individually; failed sends remain eligible. A crash between Telegram acceptance and saving can repeat an alert. Backlog beyond ten carries forward only while it remains within the freshness window; this is not a lossless archive. Pagination beyond 1,000 articles or malformed responses fail visibly. No news is interpreted as a BUY or used to modify paper trades.

The dispatcher accepts older three-scanner resume cursors during deployment and adds the news slot without resetting the existing clocks. News state commits persist even after a partial delivery failure. Run `python -m unittest -v` for feed validation, pagination failure, duplicate/update handling, partial delivery retries, batch limits, dry-run isolation, cadence migration and paper strategy attribution.

### Review notes (2026-11-02 UTC)

Crypto currently includes breakout, trend and small exploratory paper entries. Exploration is capped at $20 allocation and $1 planned risk; ordinary entries retain the $125 allocation/$5 planned-risk caps. These are distinct research strategies; five closed trades do not establish profitability. New position and exit records retain strategy metadata; older records remain unattributed (`legacy_unknown` on exit) rather than guessing their strategies. Do not infer live returns from paper results.

Stock/options coverage is a 30-symbol watchlist using IEX, with OPRA entitlement-dependent options. Sports discovery is much broader than matched book coverage: in the checked 01:22 UTC run, 1,705 discovered markets produced 39 matched games, ten reported candidates and zero qualifying BUYs. Reports now include counts for missing exact matches, assessed games below the edge cutoff, and matched-market rejection reasons. Checkout and setup-python now use current v7 releases to remove deprecated runtime warnings. No risk thresholds were changed for this prototype.
